# 博尔简历自投插件

一个面向 BOSS 直聘的 Chrome / Edge Manifest V3 扩展。当前版本为 `0.6.3`，用于把“使用 BOSS 筛选结果 → 试运行 → 单次批量授权 → 逐个投递 → 留痕”串成可控流程。

## 当前能力

- 扫描 BOSS 搜索结果页中的岗位卡片。
- 按包含词、排除词、城市和最低薪资进行本地筛选。
- 默认试运行，只高亮匹配岗位，不会发起沟通。
- 面板中的“识别 / 匹配 / 今日”均可点击筛选；点击岗位只会定位并打开详情，不会触发投递。
- 可在识别或匹配列表中勾选本轮目标；未勾选时默认从最前面的合格岗位开始。试运行会明确标出本轮目标。
- 匹配岗位可移除并恢复；移除状态会保存在本地，默认投递不会再选择这些岗位。
- 每次投递都会重新绑定当前岗位详情，并在确认“继续沟通”状态后才计入今日记录。
- 批量运行会自动依次打开左侧岗位并投递，无需用户逐个打开；页面中的 `javascript:` 链接会阻止默认跳转，避免触发扩展 CSP 错误。
- 成功判断支持“继续沟通 / 继续聊聊”、成功提示和按钮状态变化；沟通按钮点击后若 3 秒内无错误，也会按已发送记录并执行正常批次间隔。
- 默认批次间隔缩短为 3–6 秒（最低可设 2 秒）；发送成功弹出提示时会自动选择“留在此页”，避免跳转聊天页或要求人工关闭。
- 成功、失败和已沟通过的岗位都会进入本地“已处理”记录；后续批次会先排除这些岗位，再从第一个未处理岗位开始取满本轮数量，避免重复占用批次名额。
- 使用已经登录的 BOSS 账号、当前筛选结果和在线简历。
- 提供 5 / 10 / 20 / 30 / 50 个五档单次批量数量，开始前只确认一次。
- 逐个选中左侧岗位，等待右侧详情刷新后再点击“立即沟通/继续沟通/投递简历”。
- 运行中可停止；检测到验证码、访问异常、账号异常或操作频繁会自动停止。
- 保存最近 500 条扫描、设置、跳过和投递记录。
- 每日上限可配置为 1–150，并在每次真实点击前强制检查；实际可用额度以 BOSS 页面和账号状态为准。

## 安装测试

### 从 GitHub 下载

1. 点击仓库页面右上角 `Code` → `Download ZIP`。
2. 解压 ZIP，进入包含 `manifest.json` 的项目文件夹。
3. Chrome 打开 `chrome://extensions/`，或 Edge 打开 `edge://extensions/`。
4. 开启“开发者模式”，点击“加载已解压的扩展程序”。
5. 选择上述项目文件夹。

### 开始使用

1. Chrome 打开 `chrome://extensions/`，或 Edge 打开 `edge://extensions/`。
2. 开启“开发者模式”。
3. 选择“加载已解压的扩展程序”，选择本项目文件夹。
4. 登录 BOSS 直聘并进入职位搜索结果页。
5. 先在扩展设置里保持“试运行模式”，填写关键词并保存。
6. 刷新页面，使用右下角的“扫描岗位”和“试运行”。

## 本地测试

无需安装依赖，Node.js 18+ 运行：

```powershell
node --test tests/matching.test.js
```

## 已知边界

- BOSS 页面类名会变化，岗位识别采用多组启发式选择器，仍需要用真实页面持续校准。
- 当前不会自动翻页，也不会绕过验证码、风控或登录验证。
- BOSS 页面及账号额度可能随时调整；插件不会绕过验证码、登录验证或平台风控。
- 首次使用建议保持试运行，再以 5 个岗位进行真实测试；扩大批次前请检查匹配结果。

## 测试顺序

1. 离线单元测试。
2. 自己账号的搜索页试运行（零发送）。
3. 首轮对 5 个明确岗位做一次批量授权测试。
4. 检查聊天、简历附件、重复投递、弹窗和日志。
5. 确认稳定后再逐步扩大批次。

## 隐私与安全

- 所有设置、岗位处理记录和投递计数均保存在浏览器本地存储中。
- 插件不上传账号、简历或岗位数据，也不包含第三方统计代码。
- 插件只请求 `storage`、`tabs` 以及 `https://www.zhipin.com/*` 权限。
